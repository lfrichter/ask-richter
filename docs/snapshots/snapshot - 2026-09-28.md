### Componentes Chave da Pipeline RAG

1. **`TSVectorStore` (`apps/frontend/src/lib/rag/ts-vector-store.ts`):**  
   Vector store in-memory em TypeScript puro que carrega `docstore.json` e `vectors.json` (768 dimensões) sem dependências binárias nativas ou C++, viabilizando execução 100% Serverless no Vercel.
2. **`ServerlessHybridRetriever` (`apps/frontend/src/lib/rag/hybrid-retriever.ts`):**  
   Motor híbrido combinando similaridade vetorial (cosseno) com busca léxica ponderada (TF-IDF com tokenização do `natural`).
3. **`GeminiEmbeddingService` & `GeminiLLMProvider` (`apps/frontend/src/lib/ai/llm-provider.ts`):**  
   Camada de comunicação com a Google GenAI SDK (`@google/genai`), utilizando `gemini-embedding-2` para vetores de 768 dimensões e `gemini-3.6-flash` (ou `gemini-2.5-flash`) para geração.
4. **Alinhamento Multilíngue (M15):**  
   Instrução rígida no System Prompt que detecta o idioma da pergunta (`EN`, `PT`, `ES`) e responde na mesma língua, usando o contexto recuperado exclusivamente como evidência factual.
5. **Prevenção de Alucinações & Regra de Abstenção:**  
   Se o contexto factual recuperado não contiver a resposta exata, o modelo é instruído a admitir explicitamente a ausência da informação sem inventar.

## 5. 🛡️ Resiliência do Supabase & Máquina de Estados (ADR-0009)

O sistema conta com um ciclo de vida resiliente para a base de dados remota do Supabase:

* **7 Estados Operacionais Estritos:** `READY`, `PAUSED`, `WAKING`, `UNAVAILABLE`, `TIMEOUT`, `AUTH_ERROR`, `UNKNOWN`.
* **Regra de Ouro da Não-Inferência:** Erros genéricos de conexão, DNS (`ENOTFOUND`, `ECONNREFUSED`), HTTP 502/503 ou timeouts (`AbortError`) nunca são classificados como projeto pausado.
* **Restore Server-Side Idempotente (`POST /api/supabase/restore`):** Descongelamento via Supabase Management API (`POST /v1/projects/{ref}/restore`) protegido no servidor, sem exposição de tokens administrativos no frontend.
* **Polling Progressivo & SLA Calibrado:** Polling sequencial com backoff (`2s, 3s, 5s, 8s, 13s, teto 15s`), `AbortController` com timeout de 8s por probe, e SLA máximo de 300s.

## 8. 🎯 Invariantes Inegociáveis para a Evolução Sanity

Durante a execução dos Milestones **M1 a M6** do plano de transição para o Sanity Content Lake, as seguintes regras e garantias devem ser mantidas intactas:

1. **Preservação do Alinhamento Multilíngue (M15):**  
   O agente deve continuar respondendo rigorosamente no idioma da pergunta do usuário (Inglês, Português ou Espanhol).
2. **Fundamentação Factual Estrita e Abstenção (Anti-Hallucination):**  
   O agente não deve inventar dados. Se uma informação (ex: *"Qual a experiência do Richter com Kubernetes?"*) não existir no Sanity Content Lake, o agente deve se abster explicitamente.
3. **Invariantes de Roteamento de Produção:**  
   Todas as rotas do frontend devem ser relativas; nenhuma dependência hardcoded de backends externos transitórios.
4. **Desambiguação de Projetos de Software:**  
   Projetos de software continuam rigorosamente distinguidos de cursos, certificações ou formações acadêmicas.
5. **Esteira de Qualidade Zero-Trust:**  
   `npm run jidoka` (check-types, lint e build) e a suíte de testes devem permanecer verdes a cada incremento.
6. **Evolução Não-Destrutiva:**  
   A camada Sanity será introduzida de forma incremental sem quebrar as rotas e interfaces de chat existentes.
